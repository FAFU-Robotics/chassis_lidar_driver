# BUNKER MINI 2.0 · Jetson 工控机使用说明（bunker_jetson）

> 本目录 **`bunker_jetson/`** 是移植到 **Jetson / Ubuntu Linux** 的完整自包含项目，
> 参考了 Windows 版 `bunker_mini_can_control`（该文件夹与旧的 `chassis_lidar_drivers`
> 已废弃并删除），并叠加了历次现场调试的全部修改
> （融合里程计、遥控关机后保持 CAN、termios 键盘频率/点按、回放修正、全局规划、探路记忆等）。
> **所有代码与依赖均在本目录内，不引用任何外部/废弃目录**。
> 日常请在仓库根目录跑 `python3 run_local.py`（本地 TCP + 网页 `:9101`）。
>
> **云端模式已废弃，不建议调用。** 不要再开 `mock_cloud.py`、双终端
> WebSocket、`start_agent.sh` 连云端，或根目录 `run_mission.py`。
> 后续功能非必要不要再靠这条通道。

## 2. 安装依赖（一次性）

```bash
cd bunker_jetson
pip3 install -r requirements.txt
```

`requirements.txt` 内容：

```
python-can>=4.3
pyserial>=3.5
websocket-client>=1.6
websockets>=12.0        # mock_cloud 需要
matplotlib>=3.5         # view/ascii PNG 需要
```

键盘输入：Linux 走终端原生 termios（SSH 下即可用），**无需** `keyboard` 库。

可选（仅 3D 视图）：`pip3 install panda3d` 可启用 `live_airview.py` 的

（两者缺一都不影响核心功能）。

## 3. CAN 网卡启用（USB-CAN / 板载 CAN）

USB-CAN 接口名（can0/can1…）**重启后可能互换**，严禁硬编码。统一用脚本启用：

```bash
# 方式 A：USB-CAN（candleLight / gs_usb），自动识别接口名
bash bringup_gs_usb_can.sh
# 输出末尾会打印当前实际接口名，如 “OK: can1 @ 500000”

# 方式 B：板载 mttcan（如 Jetson 自带 CAN）
bash bringup_can0.sh
```

验证：

```bash
candump <上面打印的接口名>     # 能看到 0x211 心跳即正常
ip -br link | grep can
```

> 若插了 USB-CAN 但 `bringup_gs_usb_can.sh` 失败：拔插一次适配器后重跑，
> 或 `bash reset_candle.sh` 重置（严重时 `bash recover_candle.sh` 用 usbreset）。
> USB-CAN 的供电/接地点必须与底盘共地。
>
> 拉线成功后可用 `python3 drive_bunker.py --action diagnose` 快速确认心跳与状态。

## 4. 本地控制台（推荐）与已废弃的云端模式

**日常只用本地控制台**：仓库根目录 `python3 run_local.py`
（不走 WebSocket；车侧代理自带 TCP `:9100`，不必再开
`bunker-teleop.service`）。老师要求的 100Hz 遥控：笔记本浏览器打开
`http://<工控机IP>:9101`，或把根目录 `teleop_from_laptop.py` 拷到笔记本，
本机 PowerShell 跑 `--host <工控机IP>`。Cursor 里 `kb` 是 SSH 字符流，
达不到 100Hz。指令表与下表相同。需要先拉 CAN 时加 `--bringup`。

**云端模式已废弃，不建议调用。**  
`mock_cloud.py` + `run_agent.py` 的 WebSocket 双终端、以及根目录
`run_mission.py`，只留给旧流程对照。后续功能默认接到 `run_local.py` /
网页，非必要不要再设计或调用云端通道。

以下仅作归档（不建议照做）：

**终端 A —— 启动模拟云端（已废弃）：**

```bash
cd bunker_jetson
python3 mock_cloud.py
```

**终端 B —— 启动车侧代理（已废弃，请改用根目录 `run_local.py`）：**

```bash
cd bunker_jetson
export BUNKER_WS_URL="ws://127.0.0.1:9000"
export BUNKER_DEVICE_ID="BUNKER-TEST01"
export BUNKER_BIND_CODE="TEST-BIND-xxxx"
python3 run_agent.py
```

代理启动时会自动：检测 CAN 通道 → 拉线（若 DOWN）→ 先清非关键故障
（`0x441`）再切并**保持** CAN 指令模式（`0x421`，50 Hz）→ 连接云端。
遥控器已关时单独的失联位 `0x04` 属正常，不再当云端故障刷屏。

**本地控制台 / 网页支持的指令（简写；旧云端终端 A 同一套，但不要再开云端）：**

| 指令 | 作用 |
|---|---|
| `move / m v w [t]` | 运动（线速度 m/s、角速度 rad/s；带 t 行驶 t 秒） |
| `goto / g x y [speed]` | 目标点自主导航（雷达避障 + A* 全局规划） |
| `kb / keyboard` | 键盘驾驶（见 §4.1） |
| `r <名称>` | 录制轨迹（同名需 y/n 确认覆盖，覆盖带失败回滚） |
| `f <名称>` | 回放轨迹 |
| `fb <名称>` | 往返：正走 + 自动返回起点 |
| `b` | 回程（录制/回放中按下，返回起点） |
| `d <名称>` | 删除已保存轨迹（不可恢复） |
| `task <名称> [ID]` | 下发点到点运输任务（沿已录轨迹回放） |
| `t` | 列出车侧全部已保存轨迹 |
| `estop / e / s` | 急停 |
| `map / lm` [`x y`] | 工控机桌面打开雷达地图（绿空地 / 橙障碍 / 红叉过不去）；带坐标则预检该点 |
| `view / pc` / `vl` / `vm` / `vb` / `vo` | 桌面点云 / 实时点云 / 地图 / 并排 / 关窗口 |
| `lo` / `loff / lf` / `ls` | 雷达开 / 关 / 自检 |
| `query / q` | 请求立即上报一次状态 |
| `ping / p` | 下发应用层心跳 |
| `find / fo / fobj <名称>` | 自主找目标任务链（巡游→识别→靠近→返回） |
| `grasp_done / gd` | 机械臂抓取完成信号：任务链 holding（等待抓取）→ 返回起点 |
| `cancel / c / abort` | 优雅中止当前任务链并沿已录轨迹返回起点（比急停温和） |
| `odom_reset / z / zero` | 远程把导航原点重置为当前位置（新起点/搬动后校正） |
| `map_return / mr on\|off` | 运行时切换「地图优先返回」（建图完成后启用） |
| `pose_align / pa x y yawDeg` | 设置 地图系↔里程系 标定（地图原点在里程系中的位姿） |
| `map_upload / mu <file.json>` | 导入全局栅格地图（组员 SLAM 地图交付通道） |
| `go_home / go` | 返回导航原点 (0,0)（agent 启动时小车所在位置） |
| `verbose / v / smart / sm / quiet / qt` | 状态打印模式切换 |

**雷达实时图形（`map` / `view` / `vl` / `vm` / `vb`）会弹在 Jetson 工控机桌面**：

- `map` 和 `vm` 都是桌面地图窗口（绿=空地、橙=障碍、红叉=过不去、箭头=车），
  不要再把 `map` 当成「在 SSH 终端里刷一页符号」。`view` / `vl` 是点云窗口，
  `vb` 并排，`vo` 关窗口。
- 启动后 **matplotlib 窗口出现在工控机接的显示器上**（车头朝上、地图随车变），
  本终端只留一行中文摘要。没接显示器才回退带「前/后/左/右」的文字简图。
- 原理：`live_viewer.py` 在 SSH/无头会话（`DISPLAY` 为空）下会自动探测本机
  桌面 X server（`/tmp/.X11-unix` 下的 `X0` 等）并用 `~/.Xauthority` 连接，
  把窗口弹到 Jetson 桌面；`mock_cloud` 启动查看器子进程时也会把探测到的
  `DISPLAY` 传给子进程。
- 手动指定也可：`python3 live_viewer.py --display :0 --mode map`。
- 无图形界面的环境（如远程纯命令行）才回退终端 ASCII 渲染。
- 查看器子进程按 Ctrl+C 关闭时，会向车侧下发 `pc_stream off` 关流，云端
  不会再报 `Set changed size during iteration`（2026-08 已修复）。
- **在云端终端 A 按 Ctrl+C 时，若雷达查看器窗口还在运行，只关闭查看器并
  下发 `pc_stream off`，云端保持运行**（想退出云端需再按一次 Ctrl+C，或
  输入 `quit` / `x`）。此前 Ctrl+C 会把整个云端一起带退出，重启后车侧
  代理重连退避已太长导致「云端显示没检测到车侧代理」（2026-08 已修复）。
  **2026-08 二次修复根因**：旧实现用 `tty.setcbreak()` 进入终端模式时会
  保留 `ISIG` 标志，导致 Ctrl+C 被终端驱动直接转成 SIGINT → `KeyboardInterrupt`
  中断整个 `asyncio` 事件循环，`\x03` 字节根本没机会被 `read_char()` 读到。
  现改为在 cbreak 基础上**额外关闭 ISIG**，Ctrl+C 才会作为 `\x03` 字节正常
  进入按键队列，命令模式才能区分「只关雷达」vs「退出云端」。
  **排版错乱修复**：自定义终端模式初版清掉 `OPOST` 导致 `\n` 只换行不回车
  （help/日志行首随机空格、逐行右移）；现保留 `OPOST` 并置位 `ONLCR`
  （`\n` → `\r\n`），输入侧 raw 不受影响。

### 4.1 kb 键盘模式（仅调试，达不到 100Hz）

本地控制台输入 `kb` 可进键盘驾驶；真遥控请用浏览器 `:9101`。
旧云端终端的 `kb` 已废弃：

- **W/A/S/D** 前进/左转/右转/后退；**+ / -** 调档；**SPACE** 急停；**Q** 退出。
- 按键读取走 **termios 原生终端**（不依赖 `keyboard` 库、不依赖 X/图形界面），
  因此通过 **SSH 登录工控机** 即可驾驶。
- **当前下发策略（2026-08-19）**：本地 `kb` 不再斜坡、不再 50 Hz 连发 `move`。
  底盘 `0x111` 由车侧 TX 环 50 Hz 保活。旧值「每 1.0 s 刷新 + duration 3 s」
  慢于车侧过期闸 0.80 s，保活包稍晚到就被丢掉，长按像丢信号。现为：
  - **长按**：约 10 Hz（`KB_REFRESH_S=0.10s`）刷新，`duration=0.28s`。
    驾驶松键窗口约 0.20 s（不再用 0.7–1.6 s 按住窗，避免松键后继续冲）。
  - **点按**：驾驶走 `motion_held()`（单事件只认 `TAP_DRIVE_S=0.18s`），
    `duration=0.20s` 且不刷新；松开立即 `(0,0)`。松开迟滞只用于已确认长按。
  - 斜坡只在车侧 `controller.set_velocity`。SPACE 立即 `estop`。
  - `kb` **不过**雷达守卫；测避障请用 `m`。测手感时先关点云流。
- 已处理的按键判定问题（功能键 `pressed()` 仍用较长窗口；驾驶另走点按窗口）：
  1. **auto-repeat 初始延迟**：`INITIAL_HOLD_S=1.0s`、`MIN_HOLD_S=0.7s`
     仍给 Q/SPACE 等，避免功能键误松开。
  2. **SSH 批次到达**：`gap_ema` 跟踪批间空白，长按窗口 ≥2.5×历史空白。
  3. **组合键 / 松一键罢工（2026-08-19）**：SSH 终端同一时刻通常只
     auto-repeat **最后按下的键**。旧逻辑把「被抢走连发的键」当成松开，
     `motion_held()` 再叠 0.18s 点按窗口，松掉其中一个键就会整车停。
     现改为和弦粘滞：组合期间被抢走连发的 WASD 仍算按住；搭档停连发后
     不再用 1.6s 窗口继续冲。单键点按仍走 `TAP_DRIVE_S=0.18s`。
     改完后需**重启 mock_cloud 和 agent**。

> **为什么导航/避障不会像 kb 那样"丢键"**：kb 的按键在控制环里要过
> SSH + WebSocket；`fo` / `goto` / 巡游 / 回放 / 对接的传感、规划、执行
> **全部在 Jetson 本地闭环**，网络只承载一次性目标下发和状态上报。
> kb 手感差不能推论成任务链也会丢 CAN 帧。
>
> **速度平滑**：所有驱动者最终走 `set_velocity` 的统一加速度斜坡
> （线速度加速 ≤0.5 m/s²、减速 ≤1.5 m/s²；角速度 ≤1.0/3.0 rad/s²）。
> `set_velocity_now` / `stop_motion` 直通，供 ESTOP 和遥控看门狗立即停车。
>
> **WebSocket 掉线（2026-08-17）**：纯 kb/`move` 遥控 → 立即停车。
> 正在跑 `find_object` / `goto` / 回放 / 运输任务 → **不停车、不取消任务**，
> 扫描匹配与伪地图继续在车侧更新。物理急停、云端 `c`/`estop` 不变。
> 断线期间暂时没有云端监视和远程取消，连上后进度会重新报上来。
>
> **网络延迟 / 断电保护（2026-08-18）**：断网被当成「延迟 → ∞」，不是
> 单独的布尔开关。车侧 `failsafe` 按三档处理链路（`healthy` / `degraded` /
> `lost`），并给云端指令加时间戳 TTL：
> - `move`/kb 到达时 age 超过 0.8 s 视为过期，直接丢弃（因此长按刷新必须
  明显快于 0.8 s，现为 0.20 s）——**禁止迟到的遥控取消正在跑的 fo**；
> - `fo`/`goto` 超过 5 s 丢弃，避免缓冲里的旧任务在错误地点开工；
> - `estop` / `c` 永不因过期拒绝。
> 链路 `degraded`（RTT≥0.5 s 或 3 s 无包）只停遥控，本地任务继续。
> 电量危急（BMS≤12% 或底盘欠压故障）且任务仍在离开起点 → **本地中止并返航**
> （里程还有效）。Jetson **断电重启后禁止自动续开**（里程原点已丢），
> `q` 里 `mission=interrupted`，由操作员 `c` 或重新 `fo`。
> 状态上报带 `failsafe{link,rttMs,power,bootInterrupt}`。
> 软件急停救不了「延迟已经发生的那两秒」；硬实时只有物理急停 / 遥控器 /
> 底盘收不到 0x111 后的失联保护。

> 注意：进入 kb 模式前会清空终端缓冲的残留按键（避免上次命令字符串键）。

### 4.2 遥控器与 CAN 指令的优先级

BUNKER MINI 手册：**遥控器开着时优先级最高**，CAN 的 `0x111` 会被挡住，
`0x311` 里程常恒为 0。遥控器**没开**时默认待机，需 `0x421=0x01` 才进
CAN 指令模式。

关机前若停在遥控档，底盘会锁在遥控模式 + 失联位 `0x04`。旧实现只发一次
`0x421`，切不过去，云端一直显示「遥控模式⚠遥控占用」，并把 `0x04` 当新
故障每约 30 s 报一次。

**2026-08-19**：看 `0x241` 是否还在（约 0.5 s 无帧 = 已关）。已关却仍报
遥控时先 `0x441` 再在 TX 环保持 `0x421`。单独 `0x04` 不再当云端故障。
遥控器真在线且 SWB 在中档才显示「⚠遥控占用」。改完后重启 agent。

因此：

- 想用 `kb`/回放/导航，**先把遥控器关闭**（或 SWB 拨到最上再发 `0x421`）。
- 遥控模式下录制（r）能记轨迹（融合里程计：0x221 积分兜底），回放仍需
  底盘在 CAN 指令模式——代理会自动切；遥控器仍开着则无法动作。

### 4.3 r / f / fb 模式（轨迹录制与回放）

- **和 kb 的关系**：`kb` 只驾驶、不录制。录制用 **`r <名称>`**（进入键盘交互
  并同时开录制）；回放用 **`f` / `fb`**。这三种都复用同一套 kb 按键环
  （WASD / B / Q / SPACE），不是另一套协议。
- **谁开车都可以录**：录制线程只采样底盘真实运动（0x221 速度 + 融合里程），
  **不区分** 是 WASD 还是实体遥控器在开。
  - CAN 指令模式：用 W/S/A/D 开车，轨迹按 0x311 里程记下。
  - 遥控器占用时：WASD 发不出去（权限在遥控），但遥控走的路线仍会记下
    （0x311 恒 0 时用 0x221 积分兜底）。云端会提示一次，不会拿 CAN 停车抢杆。
- **回放必须 CAN**：`f` / `fb` 靠 CAN 发速度。遥控器开着会挡住回放；
  关掉遥控器（或 SWB 拨到最上），代理会切 `0x421`。
- **r <名称>**：开始录制。若同名轨迹已存在，终端会提示
  `是否覆盖? (y/n)`，Linux/SSH 下用 termios 读取 y/n，可直接输入。
- **建议用键盘录**：`r` 进入后用 W/A/S/D 开车（默认速度约 0.1 m/s）。
  点按、和弦转弯、松键停顿都按实车处理：起停边沿必采样、匀速转弯加密、
  思考停顿不写进回放。录制采的是底盘真实 0x221 + 融合里程，不是按键指令。
- **b**：录制/回放中按 b → 反向返回起点（沿轨迹逆行）。纯 `kb` 驾驶按 B
  无功能、不再刷屏。
- **f <名称>**：正向回放。**fb <名称>**：正走完自动返回起点。
- 回放采用 **里程计驱动 + 段内闭环修正**（尽量贴录制时的轮迹，不是地图绝对位姿）：
  - 以轮子里程（真实 0x311，卡死时无缝切换融合/合成里程）为目标推进；
  - 每一段的速度由左右轮位移反推，避免「录制平滑后的 v/w」和这段实际弧长对不上；
  - 纠偏瞄当前折线上的点，不瞄下一个航点终点（减少切弯、S 弯）；
  - 横向修角速度、纵向轻度加减线速度；回放不再套第二层速度斜坡
    （kb 录制时斜坡已经进了 0x221，再斜一次会把点按抹平）；
  - 轨迹文件带轮距：回放用录制时的轮距积分。和 `BUNKER_WHEELBASE` 差 2 cm
    以上会告警，但仍以轨迹为准；
  - 等待航点时每 20~50 ms 重发速度（与底盘 20 ms / 500 ms 失联窗对齐）；
  - 每航点有动态超时预算（剩余距离/当前速度），不再因固定超时提前放弃；
  - kb 录的轨迹回放仍过雷达守卫（安全）；硬挡时先停车约 1.2 s，毛刺/过人
    后继续，一直挡着才整段中止。**贴障碍录的路，回放仍可能被刹停**——
    录的时候留出车宽余量；
  - 卡死检测：里程/轮速一段时间无进展 → 判定堵住。
- 录制自适应采样上限 **0.4 s**（短于底盘 0.5 s 失联窗）；转弯约 **80 ms / 20 mm**。
  `goto` / 巡游 / 对接控制环 **20 ms**，与 `0x111` 对齐。
- 回放完成后 `on_complete` 必然回调：残缺回放（如中途被 b 打断、超时兜底）
  也会正常退出回程状态，**不会永久卡死终端**。

## 7. 导航与自主找目标（find_object 任务链）

**实战不要用键盘。** 仓库根目录执行 `python3 run_local.py`，雷达在线后
在本窗口或网页下发 `fo <名称>` 进入下面这条任务链。

> 不要再用 `run_mission.py` / `mock_cloud.py`。那是已废弃的云端中继。

调试时在本地控制台输入 `find <名称>` / `fo` 进入同一条任务链：

```
① 自主探路巡游（patrol）→ ② 视觉识别目标（vision，多帧确认防误检）
→ ③ A* 全局规划导航靠近（navigator + global_planner）→ ④ 机械臂对接（approach）
→ ⑤ 沿巡游轨迹返回起点
```

- **探路**：用 LiDAR 选最开阔可通行方向，带「探索记忆」——近期走过的方向
  会被惩罚、未探索方向获得加成，避免原地打转。
- **识别**：高反射标记聚类；**多帧确认**：先停车，连续数帧方位/距离一致
  才确认为真目标，滤掉扬尘/噪声误检。
- **规划**：在雷达伪地图（occupancy）上做 **A\* 全局规划**（含障碍膨胀 + 路径
  平滑），再交给导航器逐航点执行；导航含航向死区防振荡、大转角减速。
- 队友建图完成后，把她的全局栅格地图实现 `iter_cells` / `cell_at` /
  `world_to_cell` 接口喂给 `global_planner` / `occupancy` 即可无缝替换伪地图。
- **云端抖动 ≠ 任务中止**：探路/导航/对接速度指令不走 WebSocket。mock_cloud
  重启或链路闪断时，车侧继续执行；只有 kb/`move` 遥控才会因断线立即停车。
  需要召回时用 `c`（优雅返回）或物理急停，不要依赖「关掉云端」来停任务。

### 7.1 任务链云端监控与远程干预

> **「导航原点 (0,0)」到底指哪里？**
>
> 本系统所有 `goto` / `go_home` / `find_object` / 轨迹记录的目标坐标，都建立在
> **导航坐标系（里程系）**上。它的原点 (0,0) 是 **agent 启动（导航栈初始化）时
> 小车所在的位置**，车头方向为 yaw=0°。
>
> - 它**不是**底盘物理上电的位置。小车通电但 agent 未启动时，导航栈还不存在，
>   不存在"原点被记住"这回事；
> - 若 agent 启动前小车被搬动（或被遥控推走），原点一律按 **agent 启动瞬间的
>   位置**起算，与之前的运动历史无关；
> - 运行中可用 `odom_reset / z` 指令把原点**重置为当前位置**——换起点、或小车
>   中途被搬动后，先用它校正坐标系再继续导航。

任务链运行期间，车侧会在状态上报（`state.payload`）与地图/点云事件里带出
**结构化遥测**，云端无需依赖文字日志即可验证自主行为：

- **`mission`**：状态（recon/found/navigating/approaching/ready/holding/grasped/
  returning/done/failed/cancelled）+ 目标名 + 导航目标点 `goal`；
- **`mission.targetEst`**：目标**结构化估计**——方位角 `bearingDeg`、表面距离
  `distanceM`、半径估计 `radiusM`、中心距离 `centerDistanceM`、里程系中心
  坐标 `centerX/centerY`（从 `found` 起贯穿整个任务链）；
- **`localization`**：位姿来源 `source`（`odom` 纯里程 / `scanmatch` 本机扫描
  匹配 / `external` 外部 SLAM）与最近一次修正量 `lastCorrection`（dx/dy/
  dyawDeg/agoS），云端可判断当前导航精度是否可信；
- **`mode` / `vehicleState`**：底盘控制模式（遥控/CAN/待机）与车辆状态。
  遥控器开着才标「⚠遥控占用」；已关仍报遥控是档位残留，代理会自动切 CAN。
  单独因关机产生的 `0x04` / 「系统异常」不再当云端故障；
- **`target` 事件**：确认目标瞬间推送结构化估计；`point_cloud` / `lidar_map`
  事件同时附带 `target` 字段，`live_viewer` 地图模式可叠加目标标记。

新增云端指令（`mock_cloud` 已支持，括号内为 ≤2 字符简写）：

| 指令 | 场景 |
|---|---|
| `cancel / c` | 探路过久/走错方向时**优雅召回**：中止任务链并沿已录轨迹返回起点 |
| `odom_reset / z` | 小车被搬动/换起点后，远程把导航原点重置到当前位置 |
| `grasp_done / gd` | 机械臂抓取完成信号（机械臂方经云端上报；`arm_bridge` 通道之一） |
| `map_upload / mu <file.json>` | 建图交付后导入全局栅格地图到 A* 规划器 |
| `pose_align / pa x y yawDeg` | 设置地图系↔里程系标定（MapAlignment） |
| `map_return / mr on\|off` | 运行时切换「地图优先返回」，免重启生效 |

> **机械臂「抓取完成」信号反馈（`arm_bridge/` 独立包）**
>
> 完整任务要求：小车就位 → 机械臂抓取 → **底盘收到"抓取完成"信号** → 返回。
> 此前代码在 `grasp_ready` 后立即返回，没有等待机械臂完成抓取。现已新增
> `bunker_jetson/arm_bridge/` 桥接包补齐该环节（**不启用时行为与旧版完全一致**）：
>
> - **信号通道**（任一即可，可多通道并存取最早者）：
>   - `ws`：机械臂控制器经云端下发 `grasp_done`（联调在 mock_cloud 输入 `gd`）；
>   - `can:can1:0x3A1`：机械臂并入底盘 socketcan 总线发帧 `0x3A1`，`data[0]=0x01`；
>   - `gpio:18`：机械臂拉高 Jetson 40-pin 指定引脚（默认 pin 18，可高低有效）；
>   - `file:/tmp/grasp.sig`：联调文件（写 `grasped` 即完成，无需硬件）。
> - **启用**：`--arm-grasp-signal "ws,file:/tmp/grasp.sig" --arm-wait-timeout 90`
>   （或 `agent.conf` 写 `ARM_GRASP_SIGNAL=...`、`ARM_WAIT_TIMEOUT=90`）。
> - **行为**：就位后 `mission=holding`（等待抓取）→ 收到信号 `grasped` → 沿轨迹
>   返回；超时推 `grasp_timeout` 事件并停在原地（可重发 `gd` 或 `cancel` 召回）；
>   `cancel`/`estop` 可随时打断等待。
> - **机械臂方接入协议**、联调步骤、GPIO 接线见 `arm_bridge/README.md`。

> **「地图优先返回」**：默认返回是沿探路时记录的轨迹原路折返；开启后改用
> 已导入的全局地图做 A* 规划回程（可抄近路、避开临时障碍），建图完成后启用。

> 建图接入的云端通道（map_upload / pose_align / map_return）默认关闭、不影响
> 现有行为；队友地图交付后按 §7 说明导入即可，无需改代码重启。

## 9. 已知限制与注意事项

1. **USB-CAN 接口名不稳定**：重启后 can0/can1 可能互换。全部代码自动检测，
   不要手工硬编码；`agent.conf` 里的 `BUNKER_CHANNEL` 留空即可。
2. **遥控器开着时优先级最高**：CAN 运动指令无效。用键盘/回放/导航前关闭
   遥控器。关机后底盘可能仍报遥控模式，代理会清 `0x04` 并保持 `0x421`；
   融合里程计已解决「遥控录制里程为 0」，回放仍需 CAN 指令模式。
3. **回放精度**：回放跟的是录制时的轮式里程，不是地面绝对轨迹。kb 录、CAN 放、
   纠偏开着时，十米级室内纵向大约对齐到航点尺度，横向大约分米。打滑、斜坡、
   遥控录再 CAN 放，误差会到分米～米。没有 SLAM 钉不住厘米级重合。
   若地图/定位接入后，建议用绝对位姿取代死推算里程作为回放基准。
4. **方式三无地图 / 主线守卫也不读建图**：`ObstacleGuard` 用当前帧点云做
   近场限速/急停（`m`/goto/回放过、`kb` 不过）。伪地图只给预检和 A*，
   5 s 衰减。空地自扫曾误报「钻进桌椅」，已剔除安装件。看不见的地方
   （雷达下方、0.1 m 盲区）守卫也看不见。
5. **方式三演示脚本**只能反应式绕障，不能走「最短路径」或记忆地形。
6. **雷达与云端双网卡**：雷达走板载网口（与雷达同网段，静态 IP），
   云端走另一网口/WiFi，避免两个网段冲突。
7. **3D 视图为可选依赖**：`live_airview.py` / `pcap_replay.py` 的 3D 窗口
   需要 `panda3d`（且 pcap_replay 还需外部 `wrs` 框架），未安装时仅这两个
   可视化不可用，**不影响**雷达驱动、避障、云端、导航等核心功能。
8. `examples/` 下为附加工具脚本（get_robot_info / demo_drive / simulate_lunar_terrain 等），
   非 Jetson 主路径，可直接运行或忽略。

## 10. 快速排障

| 现象 | 处理 |
|---|---|
| 代理报 `CanConfigError` / `Network is down` | 先 `bash bringup_gs_usb_can.sh`；确认 `candump <iface>` 有 0x211 |
| **USB-CAN 插上却一直 DOWN / 小车不动** | **先跑 `sudo bash fix_candle_usb.sh`**：修复 `/etc/udev/rules.d/99-gs_usb-candle.rules` 语法错误（历史版本行尾多 `)`，导致 MODE 0666 与自动拉起失效）+ reload udev + 拉起全部 can* + 探测底盘反馈口 |
| **底盘在广播 0x211 但 agent 锁错口（小车不动）** | `sudo bash find_chassis.sh` 确认底盘在哪个口；agent 已内置「无反馈每 10s 自动重探 + 热切换」，日志见 `[底盘诊断] 重探发现底盘在通道 canX`，无需重启；也可 `BUNKER_CAN_CHANNEL=can1 bash start_agent.sh` 直接指定 |
| `未收到心跳` | USB-CAN 没插好/没共地；`lsusb` 看有无 1d50:606f；`bash reset_candle.sh` 重置 |
| 遥控模式回放不动 / 状态一直「遥控占用」 | 关闭遥控器。代理看 0x241 已停则清失联并保持 0x421；真占用则 SWB 拨到最上。重启 agent |
